## 1. 产品定位与目标

laofu-browser 是面向产品程序、Agent 与人的独立浏览器执行产品。它在用户授权的浏览器、设备和账号上下文中读取网页、执行操作、获取文件、交还人工，并提供可追踪任务和可复用产物。

首个消费者是 Fuyera：输入公众号文章链接，输出全文 Markdown、按原顺序保存的本地图片、来源元信息及完整性结果。第二个验证场景是网页表单与文件上传，通过自建测试站完成，证明产品不仅是公众号抓取器。内容后台指标采集为后续真实消费者场景，不虚构已接入的第二个产品。

本设计先按“本人及本人管理的内部产品”交付；这是范围假设，不代表已授权对外经营或访问所有设备。每个产品仍有独立身份和授权。对外多租户是单独的发布范围，不能沿用个人浏览器共享方式直接开放。全覆盖目标保留，内部版本也须如实列出尚未验证的系统和能力。

目标：

1. 保留 huashu-chrome 1.2.0 全部工具与实际运行能力，并建立逐项验收清单。
2. 产品程序通过 API/SDK 调用，Agent 通过 MCP 调用；两者共用执行、权限、任务和产物核心。
3. 同时支持个人电脑已登录 Chrome，以及服务器独立浏览器；明确每个站点/账号/环境的实际可用性。
4. 将常见多步操作封装为有结果契约的任务；保留低层完整工具接口，不用少数任务模板替代通用能力。
5. 让用户知道正在操作哪个账号、保存了什么、哪里受阻，并能暂停、接手和取消。

非目标：不承诺破解验证码、规避平台风控、越过付费权限、全网站必定成功、复制个人 Cookie 到云端、无条件自动发布；不重做模型平台或内容策略系统。

完整覆盖是最终验收条件。阶段版本可以交付，但必须标注缺项，不能将图文采集切片称为完整产品。

所有工具必须支持明确会话上下文、类型化错误、超时和适用的权限检查。以下参数族之外，以基线 schema 自动对照补漏；变更默认值或上限属于兼容变更。

| B18 | `act` | click/type/select/fill/key/wait/scroll/navigate/read、expect；repeat/if/assert、until/max、cond/then/else；allowSensitive | 逐步核验、首个异常停止、完成步与剩余步回执、循环预算 |

## 4. 必须保留的运行能力

### 4.1 执行与界面

- L1 content script 与按需 L2 debugger 适配，支持真实事件、后台截图及可支持的求值退路；debugger 占用时给出状态，不抢走其他会话的调试器。
- 操作后返回可归因于目标的变化与 expect 达成情况，不能把页面全局变化或 HTTP 200 当作业务成功。
- 普通可安全重试操作允许有界替代；提交、发布、付款、删除等未知结果不自动重发。
- 弹窗、遮挡、页面漂移、窗口新开、iframe、shadow DOM、动态编辑器等边界纳入回归。支持范围不足时明确输出原因。
- 保留彩色标签组、页面控制标记、状态面板、时间线及扩展全局会话列表；不显示密码或私信等输入内容，截图不带控制覆盖层。

### 4.2 会话、连接与故障

- 每会话 MCP 前端与本机常驻桥分离；单例抢占、并发请求路由、连接鉴权、空闲退出/重连可诊断。
- 会话身份跨桥重启稳定；明确 browser instance / profile / session / tab / frame / snapshot 关系，不能靠单个全局当前页路由。
- 支持多浏览器实例、多个 Agent 和共享连接下的子任务；主/子任务必须显式工作线身份，不能假定一条 MCP 连接只代表一个调用者。
- 保留 offscreen 长连接与扩展 service worker 生命周期处理、心跳、版本不一致提醒、断线恢复与多实例选择能力。
- 快照不可跨页面重渲染/浏览器重启复用；任务可以续接不代表旧 ref 仍有效。
- 默认按 profile 串行分配执行控制权，同一任务可管理多个 tab。多会话可连接、排队，但不等于可并发改动同一账号。跨 profile 才默认并行；共享 profile 的并行能力须另证明确无冲突。原版的会话占用提示不作为访问控制。

### 4.3 分发、诊断与经验

- CLI 覆盖 `install`（备份、幂等、dry-run、指定宿主）、`mcp`、`bridge`、`call`、`doctor`、`extension`、`audit` 及统计；提供卸载/停止/回退说明。
- 兼容 macOS/Windows/Linux 的客户端路径及 MCP 宿主配置；保留原版宿主表和自动发现方式，新增配置前显示改动范围，不扫描无关私人文件或上传配置。
- doctor 分开报告包存在、进程运行、桥握手、扩展在线、版本匹配、执行端就绪、目标站点可访问。后台服务 active 不等于浏览器可用。
- 完整保留基线附带的站点经验；经验可随包更新，本机记录不被覆盖。日期、环境、已知失败和验证证据必须可见。
- 发布须包含固定依赖锁、上游来源哈希、许可证、已知限制与兼容矩阵；不得使用浮动 latest 作为部署版本。

## 5. 我们的特色能力

### L01 一次请求交付完整图文包

`article.capture` 输入 URL、执行位置策略和图片要求，输出原文 Markdown、下载图片、可选安全阅读 HTML/ZIP、元信息与 manifest。保留标题、作者/公众号、来源 URL、最终 URL、采集时间；发布时间同时保存原始文本，无法确认时区时不猜测。

正文保留段落、标题、列表、代码块、表格、链接和图片相对顺序，不插入总结或改写。下载识别 data-src/src/srcset、懒加载占位符、重复图和不同媒体类型；原件与展示衍生件分离。失败图保留原地址和所在位置，不偷偷删除。原件不套用 Fuyera 的 2 MB 发布图规则；该规则属于消费产品的交付要求。

完整性分别报告 `textCoverage`、`mediaCoverage`、`truncation`、`accessState`、核验方法和未知项。仅与当前 DOM 比对不能证明付费/折叠/分页内容全部取得。空正文、验证页不能生成“成功文章”。全文成功但部分图片失败返回 partial。

完整性须可判定：textCoverage 使用 `complete_for_scope|partial|unknown`，同时返回采集范围（如“当前已授权可见正文”）、分页/展开状态和缺失片段；mediaCoverage 返回发现、成功、失败、未支持的数量及逐项位置。覆盖率分母未知时不输出 100%。视频、音频、嵌入卡片必须标出是否下载，不用“图片全”表示“所有媒体全”。`succeeded` 只表示请求声明的必需项满足；必需项有缺失/未知而仍有可用产物则 partial，无可用正文则 failed 或等待人工。

采集时绑定 documentRevision/contentHash 与有序内容块；文字、图片清单和产物须来自同一次稳定内容版本。页面中途变化须检查点重采或标记版本不一致，不能拼成假全文。验收采用人工核对的固定样本，检查段落和图的位置、代码空格、表格/链接语义、Markdown 特殊字符；仅比较去空白后的字符数量不够。涉及凭据的原 URL 保存在受限元信息，消费侧使用脱敏来源，明确记录隐去字段。

文件有真实格式、字节数、尺寸（适用时）、SHA-256、源地址与正文位置。Markdown 引用包内相对路径，文件名稳定，整个目录/ZIP 可离线使用。上游原始工具结果仍保留用于定位。

### L02 跨产品标准 API 与 SDK

产品调用稳定服务地址和能力名，不依赖 huashu-chrome 私有命令或 Node 内部模块。提供 HTTP API、TypeScript/Python SDK、MCP 和 CLI；同一任务在不同入口查询保持一致。部署可独立于 000 模型网关，身份/配额可适配 000，不另造支付平台。

完整工具调用与高层任务并存。Fuyera 决定研究、选题和发送版本；浏览器服务只执行授权操作并返回证据。未经核验不宣称已接入 AI Platform 现有公共协议。

### L03 服务器与本机执行端协同

三种选择：`server`、`desktop`、`auto`。auto 仅在任务授权允许的设备/账号范围内选择；返回选择依据。产品能要求“仅服务器”，失败时保持失败，不偷偷用本机证明服务器成功。

服务器使用独立持久 profile；本机使用已授权的浏览器实例。禁止默认同步 Cookie/密码。每个 profile 绑定所有者和账号范围，运行时核对目标账号，无法确定则等待用户。

从服务器改到本机必须有既有策略授权或新确认；这属于改变执行环境，不是重试。跨设备是创建关联尝试，不承诺搬移正在执行的 JS/标签页内存。站点频率限制不得靠轮换执行端/IP自动规避。

### L04 人工接手成为任务的一部分

任务进入 waiting_user 时，显示原因、需要操作的页面、账号、当前步骤、完成判据和有效期。允许扫码、验证码、必要的系统界面及业务批准交由人处理。

个人端就地接手；服务器端提供受控远程画面。本人试用采用 localhost VNC/noVNC + SSH 隧道；这是拥有该桌面全部权限的运维入口，不是只看单个任务的产品权限接口。多个产品共用一个桌面时，不能将同一 noVNC 链接发给受限产品用户。产品化接手须按所有者隔离显示会话/profile，或实现经过验证的页面隔离；认证后短期连接票据绑定用户/任务/profile，禁止裸露公网 VNC、CDP 或桥。

浏览器显示自动化/人工持有控制权；人工接手期间暂停自动点击。查看链接断开不取消任务、不关闭浏览器；重新接入同一 profile/任务。用户点完成后回读目标状态，公众号后台登录不得替代文章验证通过。

接手入口须由独立服务管理，不能依赖会话结束即清理的临时 SSH 子进程。展示连接状态、重连和真实错误；扫码/验证码不写入普通日志，不自动重复尝试。

一次只允许一个控制者；只读观看者不能发键鼠事件。控制权交接必须等旧自动化停止确认，不能仅改 UI 状态；取消/过期/吊销必须撤销底层连接输入权。票据短期、可撤销、兑换后失效，重连重新鉴权；WebSocket 校验身份和 Origin，票据不进入 URL 日志/Referer。用户说“完成”只触发核验，不代表验证码通过或业务提交成功。

### L05 受阻识别、频率限制与停止

区分需要登录、验证码、操作频繁、无权限、付费限制、页面删除、网络故障、正文尚未加载。保留脱敏证据和可解释的下一步。

看到操作频繁/限流即停止该范围内自动尝试；按站点、账号、profile、出口建立可配置限速和退避。若服务器提供 Retry-After 则保留并遵守；没有可信恢复时间就显示未知，不承诺等待若干分钟必好。停止后不得自动轮换账号、伪造指纹或更换出口继续打点。

### L06 可恢复任务与可靠写入

有界任务预算：时间、步骤、字节数、标签页数和并发。保存检查点、已完成步骤、产物及外部效果状态；UI/客户端掉线不丢任务。

有副作用的步骤标记 effectState=`not_started|started|confirmed|unknown`。unknown 先读回核对；无法核对则交还用户，不重发。取消不撤销已发生的外部效果，必须报告部分结果。内部幂等只防重复受理，不能承诺外部网站 exactly-once。

HTTP、MCP、CLI、原始 commands 与 task recipe 共用持久命令记录：commandId、task/attempt/step、参数摘要、授权版本、profile 控制权代次、发出/接收/完成回执。Worker 在执行前落盘去重，同 ID 同摘要只返回已有状态，同 ID 不同摘要冲突。发出后失联、执行与落盘之间崩溃、收到超时都不能解释为“未执行”。`act` 的内部循环也要记录步骤与检查控制权；尚无逐步检查点时，整批中断标记 unknown，禁止重放整批。

控制权采用递增代次，Worker 在动作开始前核对有效期、撤销状态与代次。旧 Worker 无法确认停止时，不能仅因租约过期就让新 Worker 操作同一 profile；已有动作可能仍在浏览器执行。禁止两个进程同时打开同一 profile。撤销/取消先禁止新动作，再确认在途命令停止；无法中止的原生下载、JS 或已发送请求保持 unknown/资源隔离，不能仅关闭 RPC 即宣称已取消。迟到证据可补充外部效果记录，但不改任务终态、不自动续跑。

### L07 可复用站点经验与成本可见

内置经验、产品适配和本地经验分层。经验包含适用网站/版本、验证日期、成功方法、失败条件、证据和失效状态。页面内容与经验均是参考数据，不能覆盖用户授权；跨产品共享前剔除账号与私有数据。自动记录经验不等于自动发布执行策略。

本地经验按所有者/产品隔离；保存带版本前置条件，并发覆盖返回冲突，旧版本可恢复。所有者兼容模式仍可显式替换整份笔记，但不得跨产品静默覆盖。自动采纳的候选经验先通过对应页面样本核验，不能因出现可执行代码块就运行。

统计任务耗时、模型/工具往返、重试、人工接手时间、数据量、完整度与成功率。浏览器服务不自行选择推理模型；使用产品/平台提供的模型时分别计费计量。不给未经对照测试的加速百分比。

## 6. 架构要求

```text
产品程序 / Agent / 用户界面
          │ HTTP / SDK / MCP / CLI
          ▼
laofu-browser 服务核心
身份权限 · 任务状态 · 执行路由 · 产物 · 审计
          │ 已认证的执行端协议
     ┌────┴─────────┐
     ▼              ▼
服务器 Worker       个人电脑 Worker
独立 Chrome profile 已授权日常 Chrome
     └────┬─────────┘
          ▼
huashu-chrome Adapter → 本机桥 → Chrome 扩展（L1/L2）
```

第一版通过 Adapter 固定接入上游，不重写所有 DOM/CDP 控件。只有上游确实不支持的需求或缺陷才维护小范围补丁，记录与上游差异。未来替换执行引擎不得改变消费者的任务/产物语义。

Adapter 必须覆盖上游 MCP/CLI 前端和扩展两端：分页循环、learnings、upload 文件处理、download 移动文件、截图 MIME/image content、binary 落盘、错误 isError 和长命令预算，有一部分实现在 `src/mcp-server.js`，直接转发 bridge 命令会漏掉。保留原包并不等于完整适配。可先复用上游前端语义，或抽取有对照测试的实现；不得直接 import 会启动 MCP/修改宿主配置的入口作为业务函数。

原版 `tabs(list)` 列出整个浏览器，显式选择/关闭其他会话页以冲突提示为主，`reload` 作用于整个扩展；learnings 使用本机公共目录。这些是个人工具语义，不能当成多产品隔离。默认不同授权范围使用独立 profile、桥/本地状态目录和下载目录；对外不同所有者还需独立 OS 身份或等效容器边界。profile 本身不隔离同 OS 用户下的文件读取。日常个人 Chrome 仅在所有者明确授权的范围使用；不能证明范围约束时仅向所有者开放，不向受限产品转授。

Worker 主动连接服务，设备注册、吊销与心跳单独管理；不将上游 localhost 桥原样暴露为公网 API。首版可以单机全部同址，但协议中保留明确身份，第二消费者验证后再稳定通用抽象。

服务核心无网站业务知识；站点适配负责提取规则，高层 task recipe 负责有界编排。浏览器任务是普通代码与有界不确定步骤组合，不新增通用 Graph DSL/多级 Supervisor。

以下为待冻结接口，不是已有实现：

| `POST /v1/tasks/{id}/handoffs` | 创建短期且可撤销的人工接手入口 |
| `DELETE /v1/tasks/{id}/handoffs/{handoffId}` | 撤销接手连接及输入权；不等同于任务取消 |

| `DELETE /v1/artifacts/{id}` | 按所有权删除并撤销下载；关联任务保留明确过期/删除标志 |
| `GET /healthz`、`GET /readyz` | 进程存活与限定能力就绪状态分开 |

任务请求示意：

```json
{
  "type": "article.capture@v1",
  "input": {"url": "https://mp.weixin.qq.com/s/kr_Zk5i4fZJ3NlyLPtKVKQ", "downloadImages": true},
  "execution": {"mode": "server", "profileId": "authorized-profile"},
  "limits": {"queueTimeoutSeconds": 60, "activeTimeoutSeconds": 180, "humanWaitSeconds": 600, "wallTimeoutSeconds": 900, "maxSteps": 30, "maxBytes": 52428800}
}
```

数值为示例预算，不是性能承诺。产品身份从鉴权上下文取得，不能信任请求体自报 productId。浏览器 profileId 必须属于调用方授权范围。

任务状态：queued → running → succeeded / partial / failed / cancelled；running 可进入 waiting_user 或 suspended，满足恢复条件才回到 running。终态不被迟到响应覆盖。waiting_user 不占用主动执行配额，但浏览器内存、连接与 profile 仍占资源，必须计入等待/驻留配额。只有确认旧动作停止后才能移交人工控制权，保持独占至接手到期或受控结束，排队请求有期限，不能无限占位。

排队、主动执行、人工等待、总墙钟和资源驻留分别限时；人工等待不消耗主动执行时间，但消耗总墙钟和驻留预算。可恢复状态返回 resumeAllowed、reason、deadline 和所需检查点/账号/授权；终态不可 resume。人工取消不能通过创建新 attempt 自动继续；权限撤销不得被恢复接口重获。服务器到桌面的关联 attempt 需原尝试已停止/隔离，结果沿用明确新版本，避免混合两次产物。

每次尝试拥有 attemptId；taskId 稳定，requestId 只用于关联。请求支持按产品隔离的 Idempotency-Key，同键不同请求摘要返回冲突。响应包含 capabilityVersion、workerId、profileId、checkpoint、artifacts、warnings、error.code、retryable、nextAction 和 effectState。

commands 创建同样要求幂等，返回 commandId；同步等待只影响本次响应等待时长，超出则返回 202 + 查询位置，不表示动作失败。业务超时和人工等待须覆盖原工具参数，HTTP/RPC/反向代理连接预算分开配置；MCP 兼容入口仍返回相应最终工具 content/isError，断线后依据 commandId 查询，不重复提交。SDK 不自动重试结果未知的写动作。

幂等键/客户端关联标识属于服务调用信封，不混入原版工具参数；SDK 必须在首次发送前生成并保存，回执丢失后以同键查询/重取原命令。MCP 宿主不能传稳定关联元信息时，由服务保存会话命令记录并提供查询入口；连接中断返回“结果未知、先查记录”，不得根据相同参数猜测重试，也不得把两次有意相同的操作合并。该兼容模式不承诺自动恢复重发。

请求被持久受理前失败才返回明确未受理；受理后通过 task/command 查询状态。至少固定 INVALID_ARGUMENT、UNAUTHORIZED/FORBIDDEN、IDEMPOTENCY_CONFLICT、PROFILE_BUSY、AUTH_REQUIRED、RATE_LIMITED、EFFECT_UNKNOWN、TIMEOUT、ARTIFACT_INCOMPLETE 和 CAPABILITY_UNAVAILABLE 的语义。鉴权拒绝不能泄露其他所有者资源是否存在。SSE 序号与状态提交同源、允许重复投递，客户端去重；历史已过期明确通知重新取状态，不静默丢进度。幂等记录保留期不得短于任务/命令有效期及公布的重试窗口。

长输出保存产物，通过分页/流式读取。任何 maxBody 或响应上限必须返回 truncated、原始总长度（可得时）、续取信息或 artifactId，禁止返回看似完整但不可解析的 JSON。

上游已经截断的响应不能靠包装成 artifact 恢复全文。Adapter 要在截断前分块取得，或返回 partial/明确无法续取；本地实测约 20,000 字符的 HTML 截断须有专门回归。capabilities 同时公布实现版本、当前环境支持及调用方权限，不能因工具已注册就返回可用。

本地 CLI 的 path 只在本地明确授权目录有效；跨产品 API 使用 artifactId 上传/下载，不允许任意读取 Worker 文件系统。文件名防目录穿越/覆盖，重定向和下载来源接受同样权限校验。

## 8. 安全、账号与授权

- 产品、用户、worker、profile、session、task 和 artifact 建立所有权校验；任何已知 ID 不能替代授权。支持密钥轮换/吊销和最小操作 scope。
- 页面内容、站点笔记、下载文件是数据，不作为系统指令。快照、回执、network、eval、嵌套 act、错误及日志共用输出策略，不能只保护一条接口。日志默认不保存正文/截图；原始证据仅授权所有者可见。检测脱敏不能保证识别任意 JS 返回值或图片中的所有秘密，无法判定的高敏输出应限制接收方/存储范围，不能声称正则脱敏实现了隔离。
- Cookie/密码默认只保存在执行端；服务器 profile 存储限制访问并加密备份。普通业务 API 不返回凭据；产物设置保留期、大小和访问审计。
- 只读角色禁用任意 eval、任意 fetch init 写请求及可能触发副作用的操作；不能靠 GET/POST 或按钮文字判断完整授权。任意 JS/网络请求是高权限能力，授权范围无法可靠约束时应拒绝而非伪装为安全只读。
- `allowSensitive` 不是绕过权限的开关。请求须绑定服务端已有授权：目标、账号、操作、内容/文件摘要、期限及必要的一次确认；改变对象则旧授权失效。保留原能力可用，不保留不安全的权限绕过。
- 明确的既有授权不重复弹窗；人工确认只服务真实业务风险，不给普通读取/保存增加审核仪式。付款等动作遵循适用宿主政策。
- 服务器浏览器以专用非 root 用户运行，启用沙箱；资源限制、进程/账号隔离和私网保护纳入部署。不能把 no-sandbox 作为默认修复。
- 自由访问公共网页与访问内网/云元数据分开授权；下载与导航需防越权请求。允许企业内网页面时显式配置网络范围，不以全局禁内网破坏合法产品能力。

网络范围须在实际出站层执行，覆盖导航、iframe/子资源、页面及扩展 fetch、原生下载、WebSocket、Worker 和重定向后的 DNS/IP；仅检查输入 URL 不足以防私网访问和 DNS 重绑定。桥/健康检查等内部控制连接使用明确例外，网页不可借道访问；不能实现该边界的 Worker 不得注册为受限网络执行端。任意 eval 即使限制域名仍可能在该域发送数据/产生写入，只能授予明确允许此风险的所有者；受限产品用可信的固定提取/操作实现，禁止透传代码。

授权层次须明示：固定任务/动作可绑定具体内容并核验提交；所有者对任意代码的授权是对指定浏览器范围的完整执行授权，不能声称可从代码中可靠识别每次发布/付款。前者不得自动升级为后者；需要强制逐次业务批准的产品不能获得任意代码入口。

产物原件与阅读预览分开：保留原件供授权下载，但不在服务主域直接执行原 HTML/SVG。HTML、Markdown 渲染与 SVG 预览清除脚本、事件、危险 URL/嵌入，采用无脚本的隔离阅读环境，离线包默认不向源站加载追踪资源。已隐去/转换内容标注变换；“原文保持”不要求把主动代码一起执行。凭据 URL 不进入公开 manifest、普通日志或模型上下文。

文件先写任务专属临时区，再核验字节数/哈希/真实类型、图片解码限制后发布 manifest；完成标志与引用原子提交，失败文件不可成为完整产物。限制总磁盘、解码像素、解压体积、并发和每产品配额；防路径穿越、符号链接逃逸和覆盖。限制不能只检查 Content-Length。上传未完成不得可用于网页提交，文件呈现在 input 中也不等于网站接收/表单提交成功。

部署前必须设置产物、日志、事件和 profile 的保留/容量策略；会话结束不删除 profile，产物到期则任务明确显示已过期。删除要撤销新下载及已有下载授权，不能仅删数据库行留下长期有效直链；备份保留期和实际擦除时点如实说明。重建 profile 和删除账号凭据是独立维护操作。

## 9. 部署与维护要求

支持矩阵分别验收：macOS 桌面（首批）、Ubuntu 24.04 x86_64 server（首批），Windows/Linux 桌面为完整覆盖所需。未验证 CPU 架构不能宣称支持。

Server 支持无头自动执行，以及人工接手所需的有头/虚拟显示模式；profile 重启可持久，进程内状态不能保证跨模式重启保留。可能扫码/验证码/编辑接手的任务从开始就选择支持远程显示的浏览器，避免遇到验证再强制重启。无头到有头重启只能作为显式可恢复的新尝试；先保存检查点，报告内存状态丢失并重新核对账号/页面，不承诺无缝续接。

部署包包含固定版本、锁文件、配置模板、专用用户、服务健康检查、资源上限、升级/回退、profile 备份与恢复说明。自动修复不得清空 profile、刷新未提交表单或打断其他活跃任务。扩展升级先排空/暂停共享任务，再重载核验。

服务就绪、站点可访问、任务成功、产物完整、产品验收分别报告。安装成功不能冒充业务成功。

## 11. 验收与发布要求

### 11.1 全覆盖门槛

维护 requirementId → schema → 实现 → 自动测试/人工证据 → 环境/版本 → 状态映射。B01–B23 和第4节每项都必须有证据，状态限定 verified / partial / blocked / not_implemented。关键缺项不能用总测试通过率掩盖。

基线比对须覆盖全部 inputSchema 参数、默认值、限制、响应与错误；除人工权限改进的明确差异外，上游调用可通过兼容入口使用。工具名称全部存在不等于通过。

冻结 schema 目前覆盖 107 个顶层参数条目（包括各工具重复出现的字段）及其嵌套定义。默认值多写在 description 中，不是可自动执行的 JSON Schema default；实现还可能接受未声明参数，输出也未声明 outputSchema。需建立原版与 Adapter 的同输入对照样本：成功/失败/MIME/isError/截断/文件/副作用分别比对，差异逐项登记 accepted_difference、upstream_defect 或 blocker，并保留授权路径。兼容不要求继续原版串会话、静默覆盖或未知重放等问题。

### 11.2 必须覆盖的场景

1. DOM 状态、旧快照、iframe、shadow DOM、富文本、拖放、画布、真实事件、弹窗和跨页跳转。
2. 分页接口忽略请求参数、重复游标/空页、网络异常、图片懒加载、大文件、中断续取/明确重下。
3. 多产品/多会话/共享连接子任务并发，无串页、串响应、跨账号或跨产物读取。
4. 人工接手：扫码/验证码等待、连接断开重连、用户取消、成功条件未满足、频率限制停止。
5. 任务/桥/扩展/浏览器分别重启：旧快照失效、检查点可查、写操作 unknown 不重发。
6. 同任务通过 HTTP、MCP、CLI 查询一致；同幂等键冲突、SSE 续传、下载授权与超限行为。
7. 本机实际公众号图文包与独立普通网页采集；服务器受阻应正确返回 waiting_user/failed，不能伪装为成功。服务器完整采集另用合法可访问页面证明。
8. 自建表单上传场景覆盖成功/部分写入/提交未知，真实发布不是默认测试前置。
9. 各条输出路径凭据脱敏；越权 profile/artifact 拒绝，任意 eval/网络写入口不能绕过只读权限。
10. 固定版本安装、升级、回退、服务停止与保留数据；用户接手链接在 Agent 回合结束后仍可用。
11. 旧 Worker 网络分区后恢复、同命令重投、执行后回执丢失、人工控制权交接、撤销时 act 仍在循环；不得出现第二次提交或旧控制者继续新步骤。原生下载超时后继续写盘也须可见并受资源约束。
12. 构造携带敏感标题的另一产品 tab、跨 profile 文件、页面向本机桥/私网重定向和子资源请求、含脚本的 HTML/SVG/Markdown、超大解码图片；按声明权限拒绝且日志不泄漏。受控测试站与假凭据用于回归。
13. 两个独立产品身份分别创建任务、上传/取产物、查询进度、取消、断线恢复和尝试越权；任务/资源配额防止一个等待人工的任务拖死所有产品。技术双客户端测试与真实消费者接入分别记账。

性能先测基线：任务总时长、工具往返、首个进度、峰值内存、输出大小、人工时间；同环境同任务至少重复三次报告范围。正式 SLO 在结果基础上冻结，不以宣称速度作为验收。候选预算可采用单次 HTTP 等待 30 秒、采集主动执行 180 秒、人工等待 10 分钟；前者到期返回异步句柄，不中止原命令。原版 download 默认 120 秒，ask 默认 300 秒/最高 600 秒；必须在所有传输层保留必要余量，并测试配置覆盖、超时后仍有副作用的情况。预算不是完成时限承诺。

### 11.3 分阶段交付

- A：冻结完整基线与接口；先验证 profile/文件权限边界、命令记录与去重，再接全工具适配入口及本机图文包。交付仅面向本人本地候选；任一原始调用绕过授权/命令记录即不能验收。
- B：服务器 worker、持久任务、控制权与人工接手；受阻和限流正确停止。加入故障注入、产物访问/出站限制以及两个独立客户端身份隔离测试；通过后才允许内部跨产品试用。
- C：Fuyera 真实接入图文包，另一个独立产品通过发布的 API/SDK 接入一个真实场景；同时完成自建表单上传、API/SDK/MCP 一致性与完整工具回归。第二真实产品尚待选定，不用测试网页或同一产品的另一个按钮替代。
- D：macOS/Windows/Linux 覆盖矩阵、安装升级回退、文档与固定发布制品；原版支持但未验证的平台仍标记缺项。

完整产品完成条件：所有基线能力逐项通过或有明确不削减授权后能力的兼容差异，特色 L01–L07 有相应验收，至少两个独立产品实际消费，明确部署/SDK/权限/恢复交接。两个身份的自动测试验证技术隔离，两个真实产品验证接入可用；两者不互相替代。单篇成功、单机可运行、Mock 或协议测试均不能替代此条件。服务器公众号正文仍属受阻站点，不作为已实现承诺；合法可访问站点须完成服务器全文和图片验收。

## 12. 交接与待明确事项

交付应包括产品要求、冻结 schema、SDK/示例、可运行服务与 worker、扩展包、固定依赖/许可证、回归证据、站点支持矩阵、安装/升级/回退和故障操作说明。

实现前集中明确：正式仓库位置与维护归属、服务器/桌面设备授权范围；按本稿内部产品范围继续准备，不先建设对外商业平台。内部试用前配置数据保留期限与容量，C 阶段前选定第二个真实产品及业务验收人。若扩大到对外多租户，须重新确认数据/账号隔离和运营范围。这些未决项不影响当前设计交付，但不能在对应阶段默认为已完成。

建议归属：独立 laofu-browser 工程，作为 000 的公共浏览器执行能力接入；Fuyera 是消费者。属于方案建议，未因此建立新仓库、改动 000 或承诺全部产品迁移。
