### 第二批：受限产品闭环与 P4 候选

#### N04 产物撤销与图文范围（G06/G08）

- 服务跟踪在途下载；删除/吊销时禁止新的下载并关闭尚未完成的服务端流。任务保留产物 ID、删除状态和不可用原因；已经下载到客户端的字节无法追回，应如实说明。
- 通用上传保留声明 MIME，同时检测支持格式的实际类型；不认识的格式以 `application/octet-stream` 下载，不推断为可安全预览。图片解码限制沿用既有策略。
- 图文采集增加有界加载/稳定判断；懒加载准备限于已授权可见正文。稳定失败、发现分页、未展开、版本变化分别保留缺项；不自动点击未知按钮或跨越付费权限。
- 现有 `article.capture@v1` 保持当前可见文档契约；自动展开/跨页采集先定义独立可选范围和预算，再决定是否进入后续增强。本轮验收重点是正确保存、正确报缺，不承诺所有站点全文。
- 范围：`src/artifacts.ts`、`server.ts`、`article.ts`、`worker.ts`、HTTP/图文回归。验收：慢速下载中删除后连接停止；重新查询显示 deleted；伪装 MIME 不进入可执行预览；延迟正文/懒加载/变化/下一页/坏图/媒体缺项的固定样本均有明确结果。

#### N05 两受限身份与人工接手验收（G07，依赖 N02）

- 每身份一个真实隔离 profile、容器/卷/桌面；不能使用 owner token 或手工写入 `isolationVerified=true` 代替正向验收。
- handoff 记录和连接票据分开；连接票据短期、单次兑换，绑定身份/任务/profile，重连新发票据，取消/过期/吊销撤销底层输入。沿用已有 Origin 与单控制者检查；本批仅提供明确的控制者模式，不伪装只读观看权限。
- 两个 SDK 分别用不同受限身份运行采集、查询、上传/下载、取消、等待/继续、断线恢复，再交叉访问任务/profile/文件/接手入口，均应拒绝。页面数据、Cookie、文件与截图使用不同的合成标记核验不串数据。
- 增加对照：要求账号的任务错配/无法核验时停止，公开 anonymous 任务无须无意义的账号确认；一个身份等待人工或超额时，另一个身份能完成合法任务；一个身份吊销不能借用旧票据继续输入；出站拒绝与公网正向同时成立。
- 范围：`scripts/isolated-smoke.mjs`、`sdk-smoke.mjs`、`handoff-regression.mjs`、`src/server.ts`、`broker.ts`、`worker.ts`、`web/main.tsx`。这只是独立服务技术验收，不改业务消费者。

### 出口选择

|选择|适用判断|购买/接入前必须核实|
|---|---|---|
|美国固定独享 ISP 代理|没有美国自有宽带设备时，适合作为第一轮小规模试用候选|固定/独享的实际范围、是否适用于全部目标域名、国家/城市稳定性、能否用于普通浏览器登录与长期连接|
|真实家庭宽带出口|有本人控制或明确授权的美国宽带节点时，最贴近所说的家庭线路|节点来源、授权、在线时间、带宽、ISP 动态换 IP 的处理；不因是家庭宽带就保证固定或免验证|
|共享轮换住宅池|本次长期登录账号不是优先选择|sticky session 的时限、节点离线后的换 IP 行为、是否只能对指定域名独享|

“静态住宅”不必然等于家庭中的物理线路。以 [Bright Data 官方定义](https://docs.brightdata.com/api-reference/proxy/rotate_ips)为例，其 ISP/static residential 是机房托管、ISP 注册的固定 IP；其不同网络的 dedicated 独享范围也不同。不能只按“纯净家庭 IP”广告用词购买。

真实家庭出口可通过 [Tailscale exit node](https://tailscale.com/docs/features/exit-nodes) 或受控 WireGuard 隧道接入。只有出口节点本身位于美国家庭宽带，才具备该网络来源；隧道软件不会凭空提供住宅线路。初期将出口限定在浏览器网关的独立网络空间，VPS 的 SSH、核心 API 和其他服务保留原路由。

### 推荐拓扑与实现切片

```mermaid
flowchart LR
  B["VPS 浏览器 / 持久 profile"] --> G["laofu-browser 出站网关"]
  G --> R["固定美国代理或授权家庭出口"]
  R --> W["目标网站"]
```

这是待实现拓扑；当前运行版本仍为网关直接出站。账号 Cookie 和浏览器配置继续存于执行端独立持久卷；出口只提供网络路径，不承担登录态保存。

1. **网关上游连接。** 为 `src/network.ts` 增加明确的出口配置；购买代理路线优先实现经 TLS 的 HTTP CONNECT，上游配置只由所有者管理。浏览器仍使用内部网关，保留 worker 禁止直接出站的网络约束。供应商凭据以受控只读 secret 文件注入网关，不进入扩展、命令行、日志或 Git；不关闭目标站点 TLS 校验，不引入 HTTPS 解密根证书。
2. **保持实际目标校验。** 每个目的地址继续执行私网/保留地址/metadata 拒绝。连接固定到已验证公共 IP；HTTPS 保留原站点 TLS/SNI。须先试验供应商是否接受 CONNECT 到已验证 IP。若供应商只接受域名并自行再次解析，就不能沿用当前 DNS 重绑定隔离证明；需要出口端可验证的同等策略或改用受控隧道，不能直接放宽现有网关。
3. **稳定身份与故障处理。** profile 显式绑定 `egressId`、预期国家和出口配置版本。记录实测出口 IP 及时间；共享同一物理出口的 profile 共用相应冷却范围。代理不可达、鉴权失败、出口漂移时停止，不自动退回 VPS 直连、不自动轮换出口。更换出口不会解除既有 profile/站点冷却，也不重放未知写任务；验证码继续人工接手。
4. **诊断和完整流量验收。** 区分 DNS、代理握手、TCP/TLS、目标 HTTP 拒绝和浏览器验证页。验证主页面、iframe/子资源、扩展 fetch、原生下载、WebSocket 使用期望出口；同时检查 IPv6、QUIC/WebRTC 等是否被隔离阻止直连。不能只检查主页面显示的 IP。验证控制 API/SSH 不受影响、代理中断不泄漏直连、凭据不进入公开产物，以及双身份原有八项隔离仍成立。
5. **供应商小样与 VPS 现场。** 先获取一个可短期试用的固定出口，用已授权的公开页验证链路；再在授权测试账号上低频完成登录、重启保留、常用操作和一次人工验证恢复，记录成功率、验证次数、掉线、时延与流量。保持浏览器版本和操作频率可比，不把一次差异自动归因为纯 IP 因素。建议观察 24–48 小时再决定长期购买；尚未设置自动任务或开始真实账号测试。

实际 Linux VPS 部署还依赖 P5 的目标系统网络入口验收；当前部署器明确只接受 macOS。可以先在现有 Mac 隔离环境验证新增出口适配，但这个方案没有授权直接修改现有 VPS，也没有把 Linux 或跨平台标为通过。

固定 IP 保留期限与独享范围；真实线路/ISP ASN 类型；明确的美国出口及漂移规则；目标网站允许清单（包括登录、邮箱、AI 网站、WebSocket 等实际需要）；HTTPS 代理或安全隧道能力；对已验证目的 IP 的 CONNECT 支持；月费、流量/并发/公平使用限制；节点来源与使用授权；试用、不可达退款或换 IP 条件。美国出口本身不等于符合每个网站的地区或账户资格。
