#### N03 显式账号范围、持久限流与容量边界（G03/G04/G05）

- 先补显式 profile 的站点/账号范围绑定与核验。公开且不要求账号的任务标记 anonymous；要求特定账号的任务从执行端取得匹配证据，无法核验则 unknown 并等待人工，不能把 profile 名称当账号证明。账号指纹留在受控状态，对外只返回核验结论。
- 限流记录由服务端保存，键覆盖站点与已绑定的账号/profile/出口范围；同一受限范围不能靠新幂等键或新任务立即重试。可信 `Retry-After` 保存原值与解析结果并执行；无可信恢复时间则保留未知，等待明确恢复操作，不猜测解除时间。
- 队列受理、执行前及人工继续时都检查限流状态；重启不丢冷却记录。已有终态/未知写入不能被“解除冷却”复活。
- 保留全局 10GiB 和单产品执行隔离，增加可配置的产品磁盘额度、队列与驻留任务上限，执行前预留额度；一个产品等待人工时，其他有预算的产品能继续。
- 管理任务自己创建的 tab：成功且已交付的采集页可按策略回收；等待人工、异常需核验、用户既有页面必须保留。达到页预算时明确停止或拒绝新建，不静默关掉其他页面。

- 验收：同站点连续两任务的第二次访问被冷却门禁阻止；重启/人工继续不绕过；两产品队列/磁盘相互约束；连续 30 次采集后由服务持有的 tab 数满足配置上限；原有用户页不受影响；不以 RSS 单次数值代替资源释放证据。

### 第二批：受限产品闭环与 P4 候选

#### N04 产物撤销与图文范围（G06/G08）

- 服务跟踪在途下载；删除/吊销时禁止新的下载并关闭尚未完成的服务端流。任务保留产物 ID、删除状态和不可用原因；已经下载到客户端的字节无法追回，应如实说明。
- 通用上传保留声明 MIME，同时检测支持格式的实际类型；不认识的格式以 `application/octet-stream` 下载，不推断为可安全预览。图片解码限制沿用既有策略。
- 图文采集增加有界加载/稳定判断；懒加载准备限于已授权可见正文。稳定失败、发现分页、未展开、版本变化分别保留缺项；不自动点击未知按钮或跨越付费权限。
- 现有 `article.capture@v1` 保持当前可见文档契约；自动展开/跨页采集先定义独立可选范围和预算，再决定是否进入后续增强。本轮验收重点是正确保存、正确报缺，不承诺所有站点全文。
- 范围：`src/artifacts.ts`、`server.ts`、`article.ts`、`worker.ts`、HTTP/图文回归。验收：慢速下载中删除后连接停止；重新查询显示 deleted；伪装 MIME 不进入可执行预览；延迟正文/懒加载/变化/下一页/坏图/媒体缺项的固定样本均有明确结果。

#### N05 两受限身份与人工接手验收（G07，依赖 N02）

- 每身份一个真实隔离 profile、容器/卷/桌面；不能使用 owner token 或手工写入 `isolationVerified=true` 代替正向验收。
- handoff 记录和连接票据分开；连接票据短期、单次兑换，绑定身份/任务/profile，重连新发票据，取消/过期/吊销撤销底层输入。沿用已有 Origin 与单控制者检查；本批仅提供明确的控制者模式，不伪装只读观看权限。
- 两个 SDK 分别用不同受限身份运行采集、查询、上传/下载、取消、等待/继续、断线恢复，再交叉访问任务/profile/文件/接手入口，均应拒绝。页面数据、Cookie、文件与截图使用不同的合成标记核验不串数据。
- 增加对照：要求账号的任务错配/无法核验时停止，公开 anonymous 任务无须无意义的账号确认；一个身份等待人工或超额时，另一个身份能完成合法任务；一个身份吊销不能借用旧票据继续输入；出站拒绝与公网正向同时成立。
- 范围：`scripts/isolated-smoke.mjs`、`sdk-smoke.mjs`、`handoff-regression.mjs`、`src/server.ts`、`broker.ts`、`worker.ts`、`web/main.tsx`。这只是独立服务技术验收，不改业务消费者。

#### N07 设备策略与账号核验（G05）

- 沿用 N03 已实现、N05 已验收的显式账号范围与核验，补同一授权账号在不同设备上的映射；不能仅凭浏览器名称相同推断账号相同。
- 再实现真正的 `auto`：仅从调用方预授权候选中选择，返回所选 profile、执行位置与选择依据；没有合格候选返回明确不可用。既有显式 profile 请求保持兼容；`server` 不能悄悄降级到 desktop。
- 首版不自动跨设备重试。未终态任务在核验旧执行停止、外部效果与授权后，才允许显式创建关联尝试。逻辑 `taskId` 保持不变，每次执行有独立 `attemptId`，保存 `taskId/index/workerId/profileId/previousAttemptId/state/effectState/checkpoint`；任务保存 `currentAttemptId`。不能用“新 taskId 加 parentId”冒充同一任务的跨端尝试。
- 任务查询返回当前尝试及历史摘要；取消作用于当前尝试并禁止后续尝试；同一任务 SSE 序列持续递增、每个事件带 attemptId。旧尝试状态保留，迟到结果只追加证据；任务已有终态则拒绝新尝试。迁移旧数据时保留原 taskId 并建立 attempt 1，现有幂等键仍返回该逻辑任务。
- 建议新增 `POST /v1/tasks/:id/attempts` 承担显式切换，必须带稳定幂等键及允许的目标 profile；旧执行未确认停止、未知外部效果未核验、账号不匹配、调用权被撤销或任务已终态时拒绝。不得迁移 Cookie、进行中的 JS 或重放未知写操作。
- 范围：`src/types.ts`、`contracts.ts`、`server.ts`、`store.ts`、`broker.ts`、`worker.ts`、两 SDK/MCP/CLI 和设备区。验收：允许集合外 profile 拒绝；位置限制不变；账号错配/未知停止；跨端 taskId 不变、attemptId 不同，旧尝试可查；终态不能被恢复；跨端尝试可追溯且没有重复外部提交。

### 顺序、工作量与恢复策略

主依赖：`N02 → N05`；`N01 + N03 + N04 + N05 + N06 → P4`；`P4 → N07/N08 → P5`。N07/N08 暂停，不提前准备跨端模拟或部署；用户明确恢复后再继续。N01/N03/N04/N06 不依赖公网隔离先通过。
